Phone-on-speaker checklist

Interview on your phone, copilot on this computer. Run through these before you start:

  • Phone on speakerphone
  • No earbuds or headphones — the computer must hear the interviewer
  • Phone 30–60 cm from the computer microphone
  • Phone volume turned up
  • Quiet room — no TV, fan or other voices
Mic test question — read it aloud, or play it from your phone on speaker: “Tell me about a time you managed a project that was falling behind schedule.”

Optional — bring your own API key. When on, detected questions are composed by a real AI model using only the profile you pasted above. When off, answers stay with the local builder on this page.

Works with OpenAI or any provider that uses the same chat-completions format — set its address in the endpoint field below.
Base address only — the page adds /chat/completions when it calls.
For example: gpt-4o-mini (faster, lower cost) or gpt-4o (stronger answers).

Where your key goes: your key is stored only in this browser on this device (in localStorage), is sent only to the API endpoint above when a call is made, and this page ships with no key built in. What is sent when Live AI is on: each detected question plus the candidate profile you pasted on this page are sent to that provider so it can compose the answer. If you don't want that sent, leave Live AI off — the local answers send nothing.

How answers work here: by default there is no server AI on this page. Suggested answers are assembled in your browser from the profile you pasted — matched to each question by keyword, structured for the mode you picked. If you turn on Live AI answers above with your own key, a real model composes the answer instead, still grounded only in your pasted profile — and the local answer remains the automatic fallback if that call fails.

Honesty rule: if no pasted fact matches a question, the answer says so and offers a transferable-skills framing instead of inventing experience. Nothing is recorded or stored, and the page makes no sound.

One disclosure: Web Speech in Chrome sends your audio to Google's speech service for recognition — that's the browser's engine, not this page sending data anywhere.

Sherpa disclosure: with Sherpa selected, recognition runs on this device and audio never leaves it. The engine is the official sherpa-onnx v1.10.46 WebAssembly runtime with the streaming Zipformer English (20M, int8) model, served as separate files with this page and downloaded only when you choose Sherpa (~55 MB in total, then cached by your browser).
